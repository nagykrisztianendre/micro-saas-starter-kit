# Support Guide

This page defines how buyers should request help and what response expectations to set.

## How to ask for help

1. Review `README.md`, `docs/getting-started.md`, and `docs/troubleshooting.md`.
2. Open the appropriate GitHub issue template:
   - Bug report
   - Support request
   - Feature request
3. Include exact commands, error output, environment details, and package tier.

## Bug reports

Use bug reports for reproducible defects in setup, runtime behavior, or documentation.

Please include:
- Reproduction steps
- Expected vs actual behavior
- Logs/screenshots
- Environment details (OS, Node, pnpm, database)

## Feature requests

Use feature requests for scope-aligned improvements (especially docs, onboarding, and DX).

Please include:
- Problem statement
- Proposed solution
- Scope and expected impact

## Support expectations

- Initial response target: within **2–5 business days**
- Resolution time: varies by complexity and reproducibility
- Support channel: repository issues (primary)

Avoid promising 24/7 or instant support unless you can reliably provide it.
